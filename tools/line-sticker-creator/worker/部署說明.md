# Cloudflare Worker／Gemini 文字安排

查證日期：2026-10-14。此服務只安排逐張文字、表情與動作，不生圖。部署範例預設未啟用；正式服務已另行部署並完成 8 張真正 Gemini 文字測試。

## 啟用順序

1. 在 Google AI Studio 建立專供此工具使用的 Gemini API 專案與金鑰，確認專案為 Free Tier；不要啟用付費帳單。不在對話、Git、網頁 JavaScript、wrangler.jsonc 或一般環境變數中填寫金鑰。
2. 使用 Workers Free 方案。先確認下方限流 namespace_id 在你的 Cloudflare 帳號未被其他 Worker 使用，若已使用，改為兩個未使用的正整數字串。
3. 在本文件所在的 worker 目錄執行以下命令。Wrangler 是部署 CLI，前端不需安裝套件或新增建置流程。執行前應取得部署授權；auth create 會開啟瀏覽器讓帳號持有人登入。

```text
npx wrangler@4 auth create microglow
npx wrangler@4 auth activate microglow .
npx wrangler@4 whoami
npx wrangler@4 deploy --dry-run --profile microglow
npx wrangler@4 deploy --profile microglow
npx wrangler@4 secret put GEMINI_API_KEY --profile microglow
```

最後一行在終端提示中輸入金鑰；輸入內容不放命令參數。若採 Cloudflare Dashboard 設定，變數類型必須為 Secret。不要將金鑰寫入本機檔案。第一次部署 AI_ENABLED=false，不會呼叫 Gemini。

4. 先核對 Free Tier、Secrets 和兩個限流 binding，再將 wrangler.jsonc 的 AI_ENABLED 改為 true，重新 dry-run 與 deploy。只使用明確指定的 GEMINI_MODEL；沒有模型自動切換、付費升級或重試。預設 gemini-3.5-flash-lite 的文字輸入輸出在查證日列為免費，但帳號可用性、模型生命週期與實際額度須在啟用時重新確認。
5. 取得實際 Worker 位址（例如 https://你的實際服務.workers.dev），在前端 sticker-ai-config.js 的 endpoint 填入「實際位址/arrange」，並將 index.html 的 connect-src 從 'none' 改為同一個精確 HTTPS origin。不要使用 *、https: 或 *.workers.dev。同步調整 config／JS 引用版本。
6. 正式頁面測試：未同意時不發請求；有同意後可看到真實建議但不自動套用；套用保留既有欄位、無文字開關與網格；照片仍只在本機；設定變動後舊結果失效；429 可繼續手動操作。瀏覽器 Network 中不得有照片、檔名或 GEMINI_API_KEY。完成後才回報真實串接成功。

ALLOWED_ORIGIN 預設 https://tsy3991.github.io，CORS 以 origin 為單位，不能限到 /TSY.Microglow-Creative/ 路徑，也不是登入或防偽機制。其他同 origin 頁面及可偽造 Origin 的程式仍可能提出請求；不可宣稱已阻止全部濫用。

## 額度與錯誤

- CLIENT_LIMITER：同 IP／Cloudflare 節點每分鐘 3 次；共用 IP 使用者可能共同受限。
- SERVICE_LIMITER：同 Cloudflare 節點每分鐘 10 次；不是全球每日硬上限，不能作為精準額度帳本。Gemini 的專案配額仍為最後限制。
- 缺金鑰、未啟用、缺少任一限流 binding、無 CF-Connecting-IP 時停止，不呼叫模型。
- JSON 最大 64 KiB、固定 8/16/24/32/40 筆、描述最多 1000 字、逐張欄位最多 300 字。拒絕未知欄位，不接受圖片或自訂 API 位址／模型。
- Gemini 最長等待 60 秒，前端最多等待 65 秒；只接受完整且可驗證的 JSON。格式錯誤、截斷、拒絕、網路失敗不回填。對前端不傳上游原始錯誤、金鑰或內部細節。
- Worker 不記錄角色描述、台詞、照片或金鑰。唯一例外是下方「搜尋字詞回報」：使用者勾選同意後，才會收到「找不到結果的職業搜尋字詞」。observability 預設關閉。Cloudflare／Google 服務本身的處理政策仍適用。
- Gemini 免費方案可能使用內容改善產品；前端需提醒並取得傳送文字同意。不要傳送照片。
- 程式無法偵測或保證帳號仍為免費方案。若管理員日後啟用 Google／Cloudflare 付費帳單，仍可能有費用；應先停用此服務再調整方案。

## 停用／回復

將 AI_ENABLED 改為 false 並重新部署，可立刻讓新安排請求回覆尚未啟用。前端亦可將 endpoint 清空、connect-src 改回 'none' 並更新引用版本。既有手動提示詞功能不依賴 Worker。正在處理的請求可能仍計入額度。

## 搜尋字詞回報（2026-10-15，選用）

用途：使用者在步驟二搜尋職業，找不到結果時，若勾選「同意匿名回報」，前端會把該字詞（最多 30 字）POST 到 `/search-miss`，讓管理者知道要補哪些職業。預設不勾；沒有 `/search-miss` 時（尚未重新部署 Worker）前端靜默失敗，不影響使用。

- 端點：`POST /search-miss`，body 只能是 `{"q":"字詞"}`；同樣限定 Origin、需要 `CF-Connecting-IP` 與 `CLIENT_LIMITER`（以 `miss:`＋IP 為 key，每分鐘 3 次），不呼叫 Gemini，`AI_ENABLED` 為 false 時仍可使用。
- 只留字詞：去控制字元、轉小寫、最多 30 字；含 `@`、網址、`.com`、連續 6 位數字以上（像信箱、網址、電話）的字串直接丟棄。不記 IP、不記其他設定。
- 兩種保存方式（可擇一或並用，皆為選用）：
  1. 綁定 KV（建議，可累計次數、保留 180 天）：`npx wrangler@4 kv namespace create SEARCH_MISS --profile microglow`，把輸出的 id 寫進 wrangler.jsonc 的 `kv_namespaces`（例如 `[{ "binding": "SEARCH_MISS", "id": "<輸出的 id>" }]`），重新 deploy。查看：`npx wrangler@4 kv key list --binding SEARCH_MISS --remote`，再用 `kv key get` 讀次數。
  2. 開啟 observability（`"observability": { "enabled": true }`），Worker 每次會輸出一行 `{"event":"search-miss","q":"..."}`，到 Cloudflare Dashboard 的 Workers → Logs 篩選 `search-miss`。保留天數依 Cloudflare 方案而定，未查證。
- 隱私：使用者可能輸入私人字詞，所以預設不勾選、只在找不到結果時才出現勾選、同一字詞每次開頁只送一次。管理者請勿把這些字詞再對外公開。
- 停用：前端取消勾選機制需改程式；較簡單的做法是在 Worker 移除 `/search-miss` 路由（回 404），前端自然靜默失敗。

### 後續怎麼查（綁定 KV 後）

在 worker 資料夾執行：

```text
node read-search-miss.mjs
```

會列出所有「找不到」的搜尋字詞與次數，由多到少。這支腳本只讀取，不修改；它呼叫 `npx wrangler@4 kv key list/get --binding SEARCH_MISS --remote --profile microglow`（旗標已用 `kv key list --help` 核對）。需要先登入 microglow profile；若 profile 名稱不同，加 `--profile 名稱`。看到次數高的字詞，就把它補進 `sticker-data.js` 的 `careers`（新增職業，或在既有職業的搜尋關鍵字 `kw` 加同義詞），重新推上 main 即可。本機沒有用真實 KV 測過，只用模擬輸出測試了整理邏輯。
若改用 observability：Cloudflare Dashboard → Workers & Pages → microglow-sticker-ai → Logs，篩選 `search-miss`，字詞在每行 log 的 `q`。
